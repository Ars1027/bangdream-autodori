# BPM 谱面解析实验

基线为 v1.2.7（`95f9724f1e3b899f695a21a96dee8c392293b8bc`）。本轮先修正谱面中的拍数到毫秒换算，保留 Bestdori JSON 和缓存作为输入。

## 修改内容

参考 [SSM 的 BMS 解析实现](https://github.com/hj6hki123/ssm-gui/blob/061d1b880e42b57698be35e9a4a841a44a684fef/scores/bms.go#L458)：先收集全部 BPM 事件，按位置排序，再换算音符时间。

旧实现边读 BPM 边解析音符。如果一个 Long 或 Slide 的节点跨过随后才出现的 BPM 事件，尾端时间会按不完整的 BPM 表计算。新实现先构建完整 BPM 表，再沿用原有 `_beat_to_time()` 换算每个音符和连接节点。

运行时代码只修改 `src/chart.py` 中的 `_process_time_chart()`。音符顺序和编号、触控生成、手指分配、minitouch 指令分块、偏移校准和首音检测均沿用 v1.2.7。

## 离线验证

```powershell
python -X utf8 _test_bpm.py
New-Item -ItemType Directory -Path data -Force | Out-Null
python -X utf8 _test_chart.py
```

新增 5 项 BPM 回归测试：跨两次变速的长条、含隐藏节点的变速滑条、BPM 顺序、变速边界上的音符、常速谱面的时间和节点编号。修改前其中 4 项失败，修改后全部通过；原有 15 项谱面检查也通过。

使用 2026-10-08 从已有缓存读取的 5 张 HARD 谱面，对 v1.2.7 和修改版进行对比。两版使用相同 Python 和依赖、1280×720 分辨率、10 ms 移动切片、100 动作指令分块和零偏移补偿。

| 谱面 | 解析结果 | 触控动作及 minitouch 指令 |
| --- | --- | --- |
| YELL（474） | 仅第 255 个音符的长条尾端时间改变 | 仅该长条的抬手时间改变，其间等待随之调整 |
| 少女レイ（496） | 完全一致 | 完全一致 |
| シカ色デイズ（655） | 完全一致 | 完全一致 |
| goodbye（388） | 完全一致 | 完全一致 |
| GO!!!（237） | 完全一致 | 完全一致 |

YELL 的该长条从第 140 拍到第 143.5 拍，期间 BPM 在第 142 拍从 75 变为 67，第 143 拍变为 61。尾端原为 114800 ms，修正为 114987.326 ms，抬手延后约 187.326 ms。修正后与同拍的另一个动作重合，因此动作列表少了一个等待项，触控动作数量保持一致。

离线对比结果不代表已经验证实机 MISS 改善；另外四张常速谱面的 MISS 需要继续排查后续环节。

## 实机对比方法

源码修改不会自动更新已有发行版中的 exe。比较时应使用同一 v1.2.7 基线、同一 Python 和依赖分别运行或构建原版与修改版。

1. 固定模拟器、画质、分辨率、流速和触控参数；关闭自动校准，固定 photogate 为 46 ms（此前测试值）。
2. 按原版、修改版交替的顺序，分别打 YELL、少女レイ和 GO!!! 的 HARD，每版每曲至少 3 次。
3. 记录 Perfect、Great、Good、Bad、Miss、FAST、SLOW，并保留完整 debug 日志。
4. 先观察 YELL 末段跨 BPM 长条，再对比整曲成绩；常速曲作为对照。

本轮不同时引入本地 BMS 读取、触控尾端延迟、指令调度或首音同步改动，以便判断谱面时间修正的作用。
